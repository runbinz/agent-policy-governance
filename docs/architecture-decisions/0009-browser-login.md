# ADR 0009: Managed browser login and shared sessions

Status: protocol, shared-session storage, API cookie/CSRF integration and console login/logout implemented. Verified with mock protocol tests, signed in-process API/database flows and a separate console presentation fixture. A real managed issuer and HTTPS browser/proxy deployment remain unverified.

Use OIDC authorization code flow with S256 PKCE, transaction-specific state and nonce, and a dedicated client audience distinct from workload, reviewer bearer and MCP audiences. Verify signed RS256 ID tokens using the managed issuer's bounded, explicitly refreshed key cache. Require exact issuer/client audience, nonce, recent numeric issuance time, expiry, and matching authorized party when supplied. Reject extra audiences and access tokens lacking the login claims. No provider access or refresh token is retained. References: [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html), [OAuth Security BCP](https://www.rfc-editor.org/rfc/rfc9700.html).

Authorization and token endpoints come from bounded discovery metadata and must share the configured issuer's origin. Redirects, proxies and automatic token-exchange retries are disabled. Token responses are bounded and provider errors remain generic. The initial supported registration modes are public PKCE (`none`) and `client_secret_post`; metadata must explicitly advertise the chosen mode, S256, code responses and RS256. Other registrations require a separate reviewed implementation. Production endpoints and the fixed `/auth/callback` redirect require HTTPS; loopback HTTP exists only in private unit-test constructors.

PostgreSQL stores hashes of a random state and browser-binding credential for five minutes. Atomic consumption prevents replay across replicas; an incorrect binding does not consume another browser's valid transaction. A shared 32-byte server secret derives independent PKCE and nonce values from random state, so PKCE secrets need not be stored in the database. Login admission is serialized and capped at 10,000 active flows. Expired flow and session credential rows are removed in bounded batches when a login starts.

Sessions use a fresh opaque random credential and a one-hour absolute lifetime. The database stores only credential and CSRF hashes, reviewer mapping and expiry. Session reads recheck the exact registered identity, reviewer, environment and tenant; disabling a reviewer or removing their mapping invalidates access. Logout revokes the shared record and audits once. Private session tables are unavailable to API/worker direct queries; only narrow API-role functions operate on them. Queries have a five-second statement timeout. Session-created/revoked audits contain an independent session UUID and reviewer scope, never hashes, cookie values or provider tokens.

The API binds state to a Secure HttpOnly `__Host-apl_login` cookie and issues a Secure HttpOnly `__Host-apl_session` cookie, both Path=/ and SameSite=Lax without Domain. A global boundary wraps the complete merged router and checks canonical Host, exact Origin, session and CSRF for cookie-authenticated mutations. Login initiation is POST with an Origin check; only GET may consume the OIDC callback, and HEAD is rejected. Session metadata returns the CSRF token to same-origin JavaScript; no provider/session credential appears in JSON. Cookie plus bearer authentication is rejected. Browser sessions cannot authorize workload or MCP calls. Existing role/grant checks still apply independently.

Reviewer authentication reads the shared session on every request. Approval/evidence reads and export downloads also recheck after their awaited work. Requests authorized before logout may already be in progress; logout cannot undo a recorded approval or external action. Dispatch continues to recheck the recorded approver and policy/grants through the existing execution path. The console aborts prior credential work, keeps CSRF data only in memory, enforces absolute expiry, and reports an unconfirmed logout with a retry action. Logout ends the application session; it does not end the identity provider's SSO session. Development token entry is exposed only when the API reports local fixture mode.

All replicas require the same browser flow key. Changing it invalidates prior session CSRF derivations and in-flight PKCE/nonce transactions. Coordinate rotation across replicas, invalidate shared session/login records, and verify re-login before reopening ingress. Restore rehearsals revoke restored sessions and clear login transactions before runtime grants, preventing an old dump from reviving those credentials.

Validate real issuer registration, HTTPS proxy behavior, replica consistency, secret provisioning/rotation and session invalidation in staging before release. Current evidence is synthetic PostgreSQL and a loopback mock issuer, with no real provider account.
