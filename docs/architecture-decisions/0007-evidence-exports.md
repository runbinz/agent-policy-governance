# ADR 0007: Scoped encrypted evidence exports

Export requests require a separate connection-scoped auditor grant. They select at most 1,000 action IDs on one authorized connection. A durable database job takes a bounded repeatable-read snapshot; no object-store operation holds a database transaction open. Generation-fenced leases prevent an expired worker from publishing readiness for another generation. Storage failures retry with a bounded attempt count.

The snapshot uses an explicit allowlist: action and policy decisions, approval and audit facts, redacted execution evidence, attempt timing, and budget settlement facts. It excludes raw requests, payment/customer references, metadata, credentials, provider account routing, and idempotency keys. The unencrypted JSON limit is 20 MiB. Before aggregation, a streaming preflight rejects more than 20,000 total action/history rows or an excessive conservative byte estimate; it never silently truncates evidence. Exports expire after one hour. Download authenticates and rechecks current requester, grant, expiry, and generation after fetching the object; it records a download audit event before returning the response.

Artifacts use AES-256-GCM with a random nonce and authenticated tenant/environment/export/generation/key-ID context. Objects have generation-specific paths. Local storage is restricted to explicit local-development mode; S3 is the deployment backend. Responses disable caching. Startup accepts up to 15 retired read keys through the bounded `APL_EVIDENCE_READ_KEYS` JSON map. Keep immutable key IDs and retain every required key until its artifacts and backups expire. Expiry revokes API access immediately. A separate leased cleanup job waits five minutes past expiry and the writer lease, deletes bounded batches without decryption keys, and retries incomplete/failed batches. Exhausted sweeps repeat hourly to remove late writes by suspended stale workers. Only the first exhausted sweep is audited; that audit is not proof that no future orphan can appear. S3 versioned objects and backups require separate retention policies.

Local tests do not establish real S3 permissions, cloud lifecycle deletion, secret-manager integration, or deployed key rotation. These remain release prerequisites.
