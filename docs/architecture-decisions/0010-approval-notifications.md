# ADR 0010: Durable approval notifications

Status: implemented and verified with PostgreSQL, a fake sink and loopback HTTP mocks. Independent review fixes verified. No real Slack workspace or message delivery has been exercised.

Queue one notification per approval generation in the same PostgreSQL transaction that creates the approval. The web approval queue remains authoritative and usable without notifications. Delivery does not approve an action, authorize dispatch, change a budget hold, or extend approval expiry. Slack links open the authenticated console; no message button performs an approval or money operation.

Routes are administrator-provisioned and scoped to one tenant/environment/connection. A job is permanently assigned to its route on first claim; an unassigned job can use the current enabled route. Recipient identity is immutable; replacing a recipient disables its old route and creates a new route. The worker selects an explicit route and transport. Slack credentials remain outside the database, and the token's workspace must match the configured route before posting. Disabled-route cleanup skips queued or expired assigned work in a separate bounded transaction, leaving live deliveries to record their outcome. Channel membership is an administrator's disclosure decision, not an application reviewer grant; every console operation still checks current identity and roles.

Private jobs use generation-fenced leases and a current-state preflight. Suppress expired, superseded, decided or cancelled approvals and disabled routes/scopes. Retry transient failures with bounded backoff and at most eight claims, including crashed attempts. Shared Slack-channel lease/cooldown coordinates workers and honors Retry-After. A process suspended after preflight can still send late; database coordination cannot fence the external service. Delivery is at least once and may duplicate after timeout or a crash. A stable client message ID is best effort and is not an exactly-once guarantee.

Messages contain fixed text, an action UUID/generation and a validated console root link. They exclude payment/customer references, amounts, raw requests, ticket text, metadata, digests, credentials and provider evidence. Use fixed plain-text facts plus a structural rich-text link; disable markdown parsing and unfurls. Transport uses the fixed Slack HTTPS API host with no redirects, proxy or automatic HTTP retries, bounded requests/responses, generic outcomes and no token values in diagnostics. The explicit fake sink records bounded, deduplicated synthetic receipts without external egress. References: [posting messages](https://docs.slack.dev/reference/methods/chat.postMessage/), [rate limits](https://docs.slack.dev/apis/web-api/rate-limits/).

Separate `--queue notifications`, `--queue exports` and `--queue dispatch` worker processes keep optional network/storage work from delaying dispatch. The default combined queue remains for local development. Production still requires secret provisioning, trusted workspace/channel setup, IAM/network boundaries, monitoring, real provider acceptance and the full release audit.
