# Required metrics extension

Read AGENTS/status/workflow and software-plan13. Keep no tenant/action/customer/channel/provider namespace/key/URI-value labels. No raw error strings. APIs below extend existing telemetry without breaking HTTP metrics.

Persistence `service_metrics::ServiceMetrics` Serialize/Deserialize, private API/worker-only `Store::service_metrics()->Result<ServiceMetrics>`; one consistent SQL snapshot,5s timeout, generic server errors, no direct runtime table access. Migration0019 only.

Fields (all i64): sampled_at_unix, held_minor, committed_today_minor, pending_approvals, oldest_approval_age_seconds:Option<i64>, unknown_outcomes, pending_provider, manual_review, oldest_unresolved_age_seconds:Option<i64>, ready_jobs, oldest_ready_lag_seconds:Option<i64>, failed_notifications, unknown_age_records, stale_dispatch_leases, ready_external_dispatches, oldest_external_ready_lag_seconds:Option<i64>. Same definitions as operations-v1 aggregated across all connections. `decisions:Vec<DecisionCount>` with {outcome:String,reason:String,count:i64}; only outcomes allow/require_approval/deny/other; reason allowlist below, unknown maps OTHER. Counts are gauges over retained rows, not monotonic counters. No IDs or raw strings returned. Retained historical data can decrease under future retention.

Reason allowlist: POLICY_AUTO_ALLOW,APPROVAL_REQUIRED,APPROVAL_SATISFIED,POLICY_HARD_LIMIT,INVALID_POLICY,INVALID_REQUEST,NO_ACTIVE_POLICY,AUTHORIZATION_REVOKED,APPROVAL_EXPIRED,BUDGET_DAILY_EXCEEDED,BUDGET_EXPOSURE_EXCEEDED,BUDGET_NOT_CONFIGURED,PROVIDER_CHARGE_INELIGIBLE,OTHER.

Telemetry public types `BusinessSnapshot` same fields + `DecisionCount` (no persistence dependency). Metrics methods:
- record_worker_tick(WorkerQueue,TickResult,Duration); WorkerQueue Dispatch/Notifications/Exports/ExportCleanup; TickResult Worked/Idle/Error.
- record_provider_call(ProviderOperation,ProviderResult,Duration); operation Context/Execute/Reconcile; result Succeeded/FailedConfirmed/Ineligible/Pending/Unknown/Timeout. Context Ineligible means verified unsupported Charge, not an availability fault.
- record_internal_dispatch(Duration) excludes provider network and human waiting.
- set_business(BusinessSnapshot), business_failed(). Initial collector up=0 until first success. Failed collection retains last values and sets up=0; expose sample timestamp and unknown-age counts. Validate/clamp malformed/nonfinite values and map unknown labels to OTHER/other. Bound decision cardinality independently of input vector size.

Metric names: apl_worker_ticks_total{queue,result}, apl_worker_tick_duration_seconds histogram{queue,result}; apl_provider_calls_total{operation,outcome}, apl_provider_call_duration_seconds histogram{operation,outcome}; apl_internal_dispatch_duration_seconds histogram; apl_business_collector_up, apl_business_sample_timestamp_seconds; gauges apl_budget_held_minor, apl_budget_committed_today_minor, apl_pending_approvals, apl_oldest_approval_age_seconds, apl_unknown_outcomes, apl_pending_provider, apl_manual_review, apl_oldest_unresolved_age_seconds, apl_ready_jobs, apl_oldest_ready_lag_seconds, apl_notification_failures, apl_unknown_age_records; apl_policy_decisions{outcome,reason}. Omit unknown age gauge values (do not substitute zero).

Provider Unknown/Timeout are indeterminate outcomes, including transport/context/parse ambiguity; FailedConfirmed is a verified business failure, not a transport outage. Alert on indeterminate rates/ages, never automatically mutate controls or release funds. Reconciliation failures are reconcile Unknown/Timeout outcomes. API+worker replicas publish duplicate global DB gauges: aggregate with max, not sum. Process counters/histograms aggregate normally and reset on restart.

Coordinator polls private DB snapshot every15s only when metrics configured; API serves existing protectedmetrics. Worker metrics require APL_METRICS_TOKEN and explicit loopback APL_WORKER_METRICS_BIND together; each worker needs a unique bind address. No public listener or implicit secret. Instrument optional wrappers so existing tick_external calls remain compatible. Test fake provider outcomes and timeout without real egress.

Alert files observability/alerts.yml and alerts.test.yml: collector failure/staleness (>120s), unknown/manual backlog age, approval age, queue lag, notification failure, provider/reconcile indeterminate fraction with minimum call volume, internal p95 target breach. Thresholds provisional engineering examples, no availability commitment. Tests must include no-data/zero traffic and healthy vs firing cases using promtool; no actual alert delivery configured.

Forward0020 extends the frozen0019 aggregate: external ready jobs are nonclosed queue rows available now without an active lease; stale leases are expired nonnull leases among these rows. Lag is clock minus available_at. New gauges apl_stale_dispatch_leases, apl_ready_external_dispatches, apl_oldest_external_ready_lag_seconds (omit unknown). Alert on sustained expired leases and externalready lag, plus configured API/worker target up==0; process down detection is separate from duplicate global DB samples.
